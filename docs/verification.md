# 实测记录与设计取舍

主文档只讲这个应用是什么、怎么用。这里放逐轮真机实测的采样记录、实现细节和踩过的坑，供想接手或想改代码的人查。

实测机型：**vivo V2359A / Android 16（API 36）/ 1080×2400 / 刘海屏**，媒体库共 177 条视频记录。文中提到的 `nXX_*.png`、`rX_*.png` 是当时 adb 截屏的文件名，截图含手机相册真实内容，不入库。

## 行为细节

- 画面一律按原比例完整显示：等比缩放、长边贴边、短边留黑，不裁切、不拉伸、不放大。竖屏视频在横屏下也是原样居中（实测 1080×1920 的视频在 2400×1080 里显示成 608×1080），字幕、水印、账号 ID 这类贴在画面边缘的信息不会再被切掉。封面缩略图用同一套 `FIT_CENTER` 铺法，和首帧对得上，切换时不跳。
- 视频区域永远是整屏（竖屏 1080×2400、横屏 2400×1080），控制条不再吃掉任何一条底部区域：播放中整条收起，暂停时才浮在画面之上。实测竖屏播放中 `PagerView 0,0-1080,2400`、控制条标志位 `G`。
- 双击快进/后退 10 秒：判定窗口 300ms、两次落点距离不超过 72dp，左半屏后退、右半屏前进。为了留出这个窗口，单击暂停延后 300ms 执行；一旦拖动手势成立就立刻取消待定的单击，所以滑动换片不受影响；长按加速优先于双击（长按触发时同样取消待定的单击）。定位结果夹在 `0 ~ 时长-300ms`，和进度条同一套规则。
- 选片面板支持搜索与排序：搜索框按片名或目录名过滤（不区分大小写，边打边筛，标题行变成「命中 N/总数 条」），序号始终按完整列表算，过滤不会让「跳到第几条」错位。排序四档：时间（`DATE_ADDED` 倒序，默认）/ 名称（不区分大小写）/ 大小（降序）/ 目录（同目录聚在一起，目录内按时间）。点排序 tab 只换列表和 chip 高亮，面板原地不动（不收起、不重新拉起、不重播入场动画），已输入的搜索词和过滤结果跟着新顺序重算；行内缩略图先查内存缓存（`VideoRepo.peekSmall`），命中就直接贴上去，换序时不闪白。换排序时停在当前这条视频上（不重新解码，播放不断），序号标签和退出位置一起更新；排序方式存 `SharedPreferences`，重开应用还是它。
- 换序不动画面：`PagerView.reorder()` 只改列表、名次和邻居封面，当前页直接按「视频已经透着」处理（`alpha` 当场置 0，不走 120ms 淡出）。原来走 `setPosition + markVideoPage` 会先把该页封面盖回画面再淡出，面板后面的画面就闪一下。
- 控制条整体抬到系统手势带之上：按 `navigationBars`/`systemGestures` 的真实 inset 计算（本机竖屏导航带 54px，再加 8dp 余量 = 78px），横屏时手势带在左右两侧，底部只留 10dp。进度线不再压在屏幕最下沿，拖它不会被系统判成上滑切应用。
- 每条视频的播放进度按 `MediaStore` id 存在 `SharedPreferences`，回到该条时从上次位置继续（片尾 2 秒内视为已播完，从头开始）。退出时还会记住「最后在看哪一条」，重开应用直接回到那一条（按 id 匹配，扫描顺序变化也不怕）。
- 实况照片的动态 mp4 会被过滤掉（识别 MediaStore 的 `is_live_photo` 及厂商 `live_photo` 字段），列表里只剩真正的视频。视频条数没有上限：实测那台手机显示 100 条，是 177 条记录里过滤掉 77 条实况照片动态 mp4 后剩下的真视频。

渲染层次（自下而上）：`SurfaceView`（视频） → `PagerView`（封面） → `Overlay`（控制）。封面不透明时挡住视频，首帧渲染后当前页封面淡出，于是看到的是实时画面；手指一开始拖动就恢复封面，滑动过程只搬运 3 张位图，与解码无关，低配机也不掉帧。`content`（视频 + 封面 + 徽标）永远铺满整屏，控制条只在暂停时叠在画面之上，不再向画面要边距。控制条空白处不消费触摸，竖向滑动照样落到翻页层；它整体 `GONE` 时触摸全部穿透到翻页层，所以播放中依然能滑动换片。

体积轨迹：33 KB（最初）→ 37 KB（细进度线 + 图标徽标 + 横屏按钮 + 系统选片对话框）→ 41 KB（自绘选片面板 + 手势带避让 + 后台 Surface 重绑）→ 53 KB（双击快进 + 选片搜索/排序 + 视频信息面板）。之后的横屏真全屏、画面等比、竖屏隐藏功能区、三档循环都没让包变大；最后那轮就地换序又写了 384 字节 dex，压缩后正好吃掉 zip 对齐的余量，包仍是 53,720 字节。

## 第一轮至第五轮实测

- 冷启动无崩溃（`logcat` 无 FATAL/AndroidRuntime），权限申请一次通过后自动扫描；实况照片被过滤掉 77 条，列表只剩 **100 条真正视频**，选片面板里也只有这 100 条。
- 竖屏真全屏：视频区域 `0,0-1080,2400` 整屏，播放中控制条 `GONE`（`dumpsys` 标志位 `G`），点一下暂停才淡入 `0,2049-1080,2400` 浮在画面之上（`n31_portrait_paused_loop.png`）。旧的「视频区域 1080×2054 + 控制条 1080×346」分块已取消，控件不再向画面要地盘。
- 横屏真全屏：点「横屏」后视频区域 `0,0-2400,1080`，正在播放时整条功能区 `GONE`（`dumpsys` 里 `LinearLayout` 标志位从 `V` 变 `G`），屏幕上没有任何控件（`n24_landscape_playing.png`）。点一下暂停，功能区淡入浮在画面下方，播放三角同时出现（`n23_landscape_paused.png`）。播放中上下滑动仍能换片（实测从 100/100 连滑到 39 前后）。
- 循环三档：点标题右侧 chip 依次变「顺序播放 → 单条循环 → 列表循环」。单条循环：第 100 条播到 0:23 结束后没有翻页，直接回到 0:02 重播（`n33_single_loop_replay.png`）；列表循环：第 100 条播完自动跳回第 1 条（`n34_list_loop_wrap.png`）；`force-stop` 后重开，档位仍是「列表循环」且回到上次那条（`n35_loop_persisted.png`）。
- 画面等比完整显示：竖屏 9:16 视频在竖屏整屏里显示成 `1080×1920`（上下各留 240px 黑），在横屏里显示成 `608×1080`（左右留黑、不拉伸）；横屏 16:9 视频在竖屏里是 `1080×608` 居中，连字幕条带歌词框整块都在画面里。最直接的对照是同一条把字幕和账号水印贴在画面底部的竖屏视频：这一轮整块都露出来了，旧版铺满裁切时正好被切掉。
- 封面与首帧用同一种 `FIT_CENTER` 铺法，换页、出首帧时画面不跳、不再出现「先放大一点再定位」的观感。
- 上下滑动翻页、松手惯性吸附、连续自动播下一条均正常。
- 单击暂停 → 中央常驻白色三角图标；恢复播放 → 双竖条闪现后淡出（`n6_badge_paused.png`、`n7_badge_flash.png`），不再用「已暂停」文字。
- 长按 → 「2.0x 加速」，**松手后恢复原倍速且不会误触发暂停**；加速途中自动换页，标签仍如实显示当前速度（`n8_boost.png`）。
- 进度线点按直接跳位（`n11_tap_seek.png`：0:01/0:11；复测点中间 → 1:34/3:15）、横向拖动精确定位（复测拖到最右 → 3:04/3:15）；在进度线上竖向起手滑动会转交给翻页层，照样换视频（复测 22→23，`n10_handoff2.png`）。
- 进度线本身位于 `y 2226-2304`，距屏幕底沿 96px；从屏幕最下沿（y=2380）上滑交给系统手势，翻页层不会抢走。
- 点「N/总数 ▾」滑出选片面板，缩略图 + `#序号 · 时长` + 当前条高亮「播放中」，打开时自动滚到正在播的那条（`n15_picker_sheet.png`）；点一条实测 22 → 21。
- 点右下「横屏」按钮进入横屏，按钮变「竖屏」，画面重新按原比例适配（`n3_landscape.png`）。测试提示：`adb shell settings put system user_rotation 1` 转不动这个应用（方向由应用自己控制），必须点应用内的「横屏」按钮。
- BACK 退出再进来回到上次那条（`n12_relaunch.png`：8/100），不是从第一条开始。
- 播放中按 HOME 再进来：画面照常（`n16_after_home.png`、`n17_after_settings.png` 切到系统设置再回来，进度 5:04 → 5:34 连续），不再出现「有声音黑屏」。暂停着切走再回来仍是暂停，并重新显示播放三角（`n21_return_while_paused.png`）；改完控件显隐逻辑后复测：HOME 出去再回来 0:10/0:23 继续播、画面正常（`n29_return_from_home.png`）。
- 选片面板在控件改动后复测无回归：点「100/100 ▾」照常滑出，`#95`–`#100` 缩略图 + 时长 + 当前条「播放中」都在（`n30_picker_still_ok.png`）。

## 第六轮实测（双击快进 + 选片搜索/排序 + 信息面板）

- 双击快进：竖屏播放中双击右半屏 → 屏幕右侧亮出「10 秒 » 0:15」提示条，功能区仍然收起、播放没被打断（`r6_b_seek_fwd.png`）；再双击左半屏 → 左侧「« 10 秒 0:04」，右侧提示同时消失（`r6_c_seek_back.png`）。横屏暂停后双击左半屏 → 左侧「« 10 秒 0:03」，进度线和时间同步跳到 0:03/0:16（`r6_m_land_seek_back.png`）。
- 单击/长按/滑动无回归：单击一下 → 暂停、播放三角出现、功能区淡入（`r6_d_single_tap_pause.png`，标题行已是「信息 + 单条循环」两颗 chip）；上下滑动照常换页并自动接上下一条（`r6_k_after_swipe.png`）。
- 选片搜索：输入 `amera` 后标题行变「命中 70/100 条」，列表只剩 `Camera` 目录那 70 条，序号仍显示 `#91`、`#93`… 这些全列表名次（`r6_j_search.png`）。
- 选片排序：点「大小」→ 当前这条从 `#21` 变成 `#87` 且仍高亮「播放中」、底部序号标签同时变 `87/100`（`r6_i_sort_size.png`）；点「目录」→ 同目录聚在一起，当前条落在 `#28`（`r6_n_sort_folder.png`）；`force-stop` 重开后排序仍是「大小」，且回到同一条视频的 87/100 位置。这一版点 tab 会把面板收起来再重新拉起（排序要回 Activity 重排、然后重开面板），观感上像闪了一下 —— 第七轮改成就地换序。
- 信息面板：点标题右侧「信息」→ 卡片显示 720×1280 / 0:15 / 3.3 MB / 1.82 Mbps / `avc` / `mp4` / 60 fps / Download / 完整路径 / ID 1354 / URI（`r6_f_info_extractor.png`）；面板内可下滑看到 加入时间、当前进度 0:09/0:15、播放速度、循环方式、列表排序（`r6_g_info_scrolled.png`）。编码/码率/帧率/旋转来自 `MediaExtractor` 的轨道格式（异步取，晚到一步再刷新一遍），分辨率/时长/大小/目录/路径/ID/URI/加入时间来自 `MediaStore`，当前进度/倍速/循环/排序来自播放器实时状态。取不到的字段显示「未知」，不猜。
- 踩到的坑：`MediaMetadataRetriever.extractMetadata` 在本机 SDK 的 `android.jar` 里只剩 `int` 键的 @hide 重载，反射按公开文档的 `String` 键取在这台 Android 16 真机上拿不到方法（`method=null`），改成 `MediaExtractor` + `MediaFormat` 的字符串键后一次通过；`compareBy(comparator){...}` 在链式 `thenByDescending` 前推不出元素类型，显式写成 `compareBy<VideoItem, String>`；`ScrollView` 没有公开的 `LayoutParams` 内部类，用父类 `FrameLayout.LayoutParams`。

## 第七轮实测（选片面板点排序 tab 改为就地换序）

- 播放中暂停 → 点「61/100 ▾」拉起面板（排序「时间」，当前条 `#61`）→ 点「大小」：面板原地不动，列表直接按大小重排，当前条变成 `#70` 且仍带「播放中」高亮，chip 高亮从「时间」移到「大小」，标题行「共 100 条」不变（`r7_7_sheet_after_tab.png`，点完约 200ms 采样，没有收起也没有重新拉起）。
- 关掉面板后底部序号标签是 `70/100`，和面板里的名次对得上（`r7_6_sheet_before.png` 是换序前，`r7_8_search_then_name.png` 是搜索框输入态）；播放没中断、进度没重置。
- 换序时行内缩略图不闪白：`VideoRepo.peekSmall(id)` 命中缓存就直接画上去，不再先 `setImageDrawable(null)` 等一次异步回调。
- 换序时后面的画面闪动（补修）：原因是 `applySort` 走 `data = / setPosition / markVideoPage`，当前页的封面会先被盖回画面（alpha 0→1）再淡出 120ms，面板上方那截画面就闪一下。改成 `pager.reorder(items, at)`：先取消吸附动画，再一次性把当前页 `alpha` 直接置 0（不用 0 时长动画，它也要下一帧才生效、会露一帧封面），邻居槽位照常重贴。包体仍是 53,720 字节。
- 踩到的坑：`onSort` 回调里想引用正在构造的 `PickerSheet` 局部变量 `s`（Kotlin 报 `unresolved reference 's'`，因为 lambda 属于它自己的初始化表达式），改成走 `sheet?.updateSort(...)`。
- 测试提示：`uiautomator dump` 在功能区 `GONE`（正在播放）时只会导出一个空节点，看到「dump 没内容」先确认界面状态，别误判成面板没打开。

## 修过的问题清单

长按松手被同时当成单击导致暂停；旋转时 `applySurfaceSize()` 读到的是旋转前的旧屏幕尺寸；换页时倍速标签被写回常速；`msAt()` 运算符优先级导致进度换算失效；选片面板第一次运行崩在 `AdapterView.addView`（ListView 的行不能自己 addView）；加权行在竖向 LinearLayout 里写成 `width=0` 导致列表宽度为 0 看不见；切后台回来有声音没画面；横屏铺满裁切掉字幕。

注意：用 `adb install -r` 覆盖安装会杀掉进程，`SharedPreferences` 里来不及落盘的「最后在看哪一条」会丢，看起来像「每次都从第一条开始」。正常 BACK 退出再启动则是正确的。
